# EXPERIENCE BIBLE

## Project: Janhvi × Krish

### Interactive Save-the-Date

**19–20 November 2026 · Jaipur**

---

# 1. THE CORE IDEA

The guest receives a link.

No thumbnail screaming “SAVE THE DATE”.

No couple photo.

No wedding hashtag.

No flowers.

No “Two hearts, one journey”.

The first thing they see is a strange, minimal digital system.

The guest should NOT immediately feel like they are watching a wedding invitation.

They should feel like they have accidentally entered a strange little digital system, gradually realise what is happening, and then be asked to participate.

The wedding reveal should be the plot twist, not the opening announcement.

---

# 2. CREATIVE NORTH STAR

The entire experience follows one principle:

> **The website knows something the guest doesn't.**

It reveals information gradually.

The desired emotional journey is:

**confusion → curiosity → suspicion → realisation → amusement → participation**

If someone screenshots the experience and sends it to another guest saying:

> “What did Janhvi send you?”

We've won.

The desired reaction is:

> “WHAT THE FUCK IS THIS?”

followed by:

> “Wait this is actually so cool.”

---

# 3. VISUAL LANGUAGE

The aesthetic is:

### Minimal / digital / mysterious / slightly unsettling / funny

Think:

- black or near-black background
- extremely clean typography
- oversized numbers
- terminal/UI elements
- loading states
- tiny system messages
- subtle glitches
- cursor movements
- notification sounds
- progress bars
- restrained animation

The aesthetic should feel like:

> **Apple-designed operating system that has somehow become involved in your marriage.**

Do NOT make it:

- neon cyberpunk
- hacker movie aesthetic
- Matrix green text
- cheesy futuristic holograms
- generic AI sci-fi

The experience should feel like an extremely polished operating system that has somehow become involved in a wedding.

---

# 4. TYPOGRAPHY

Primary:

**monospace / technical font**

Secondary:

clean modern sans-serif.

The first half should feel like a system diagnostic.

After the wedding reveal, typography can become slightly warmer.

The visual transformation itself tells the story.

---

# 5. SOUND

Sound is OFF by default.

A tiny sound icon appears once interaction begins.

If enabled:

- subtle system startup
- soft keyboard clicks
- notification ping
- loading ticks
- installation sound
- completion sound

No wedding song.

No Bollywood.

No voiceover.

The absence of music makes the reveal stronger.

Browser autoplay restrictions must be respected. Sound should only begin after user interaction and only if the guest enables it.

# 25. GUEST IDENTIFICATION

Every individual invited guest receives one unique invitation link.

Example:

`yourdomain.com/i/8Kf92x`

The token must be random and unguessable.

The URL must not expose:

- guest name
- phone
- email
- household
- family information

The system internally maps the token to the invited individual.

Guests never need to enter their name.

---

# 26. PERSISTENT GUEST EXPERIENCE

The unique invitation link remains associated with that guest.

If a guest returns after responding, the system recognises their previous response.

For example, if Rahul previously selected YES:

> **WELCOME BACK.**

> **STATUS: INSTALLED**

> You already made this decision.

Then show:

### **19–20 NOVEMBER 2026**

### **JAIPUR**

Options:

### [ CHANGE RSVP ]

If Rahul changes the response, the new response becomes the current response and the previous response remains in RSVP history.

If the guest previously selected MAYBE:

> **STATUS: PENDING**

If the guest previously selected NO:

> **STATUS: DECLINED**

Returning guests must not be forced through the entire original experience again.

---

# 27. RSVP MODEL

The Save-the-Date records only the individual guest's own RSVP.

Possible responses:

- YES
- MAYBE
- NO

There is NO plus-one system at this stage.

There is NO guest-name collection.

There is NO relationship collection.

There is NO guest-to-guest linking.

There is NO assumption that an individual guest has permission to bring someone.

Household/group information is internal administrative data only.

The actual wedding invitation, shared later, will handle detailed guest management.

---

# 28. SOUND CONTROL

Sound remains OFF by default.

Once the guest has interacted, a small sound control may appear.

If enabled, the system can use:

- startup sound
- keyboard clicks
- notification ping
- loading ticks
- installation sound
- completion sound

No music.

No voiceover.

No Bollywood.

---

# 29. EASTER-EGG SYSTEM

Easter eggs are a major part of the experience.

The website should feel responsive and alive.

Examples:

If the guest waits too long:

> `Still there?`

Then:

> `We appreciate the commitment.`

If they press Back:

> `Going backwards is currently unavailable.`

If they refresh during installation:

> `Please don't interrupt the marriage.`

If they try a disabled interaction:

> `Nice try.`

If they return after YES:

> **STATUS: INSTALLED**

> `You already agreed to this.`

If they return after MAYBE:

> **STATUS: PENDING**

If they return after NO:

> **STATUS: DECLINED**

These should be implemented intentionally and contextually, not as random jokes.

---

# 30. ANALYTICS

The system should track meaningful guest behaviour.

Examples:

- invitation opened
- screens viewed
- reveal reached
- installation reached
- warning viewed
- RSVP selected
- RSVP changed
- Easter egg triggered
- returning visit

For each guest, the system should be able to determine:

- whether they opened
- when they first opened
- when they last opened
- how far they progressed
- where they abandoned
- what RSVP they selected
- when they selected it
- whether they later changed it

# 32. DATA PRIVACY

Collect only information required for the Save-the-Date experience.

Do not collect:

- precise location
- contacts
- microphone
- camera
- unnecessary personal information

Basic device/browser information may be used for technical analytics and QA.

---

# 33. WHAT IS EXPLICITLY BANNED

Do not introduce:

- conventional wedding invitation design
- flowers
- couple photography
- cinematic wedding montage
- generic AI bride/groom imagery
- boarding pass concept
- passport concept
- newspaper concept
- Spotify concept
- magazine concept
- Polaroids
- Google Maps concept
- countdown timer
- romantic wedding clichés
- hearts
- rings animations
- wedding bells
- generic cursive wedding fonts
- immediate "SAVE THE DATE" headline
- wedding song
- Bollywood music
- voiceover
- detailed wedding information
- venue details beyond Jaipur
- function/event details
- accommodation information
- itinerary
- plus-one management
- manual guest-name entry

The phrase "SAVE THE DATE" does not need to appear at the beginning. The experience should reveal itself naturally.

---

# 34. MOBILE-FIRST

The experience is primarily designed for phones.

Primary environments:

- iPhone Safari
- Android Chrome

Desktop should also work.

The website must account for:

- safe areas
- viewport height
- touch targets
- animation performance
- font loading
- mobile browser behaviour
- network interruptions

The experience should feel like a phone-native interactive experience that also happens to work on desktop.

---

# 35. CREATIVE NORTH STAR

The website should never feel like a template.

It should feel like a small, strange, highly polished digital experience that happens to announce:

> **Janhvi + Krish**
>
> **19–20 November 2026**
>
> **Jaipur**

The guest should finish thinking:

> **"That was not a normal Save-the-Date."**
